# 포트폴리오 사이트 개선점 리스트 (인사담당자·채용 관점)

전체 코드 점검 후, 포트폴리오로서의 기능 강화와 인사담당자 임팩트를 위한 개선점을 카테고리별로 정리했습니다.

---

## 1. 첫인상 & 진입 경험

| # | 구분 | 현재 상태 | 개선 제안 |
|---|------|-----------|-----------|
| 1.1 | **Welcome 모달** | "Kyle Portfolio OS", "Spatial web experience" 등 개발자 위주 문구 | 인사담당자용 한 줄: "1년 차 풀스택 개발자, 기획부터 배포까지 End-to-End 개발합니다" 등 **역량 요약** 노출. "Enter Portfolio" 대신 "자기소개 보기" 또는 "시작하기" 등 직관적 CTA |
| 1.2 | **타이틀/SEO** | `TAEMIN KIM Portfolio \| KyleOS (React)` | `김태민(Kyle) \| 풀스택 개발자 포트폴리오` 등 **이름 + 포지션**이 검색·북마크에 보이도록 변경. `meta description`, `og:title`, `og:description` 추가 (SNS/검색 미리보기) |
| 1.3 | **첫 화면 정보** | 웰컴만 닫으면 빈 데스크톱 + Dock. "뭘 먼저 열어야 하지?" 느낌 | 웰컴 닫을 때 **About Me 창 자동 오픈** 옵션, 또는 데스크톱 중앙에 "About Me 클릭해서 시작" 같은 **가이드 문구/버튼** 1개 노출 |
| 1.4 | **메뉴바 로고** | `image/Kyle.png` 상대 경로 | Vite 기준 `public` 폴더는 루트에서 서빙되므로 `/Kyle.png`로 통일. `image/` 폴더 없으면 404 위험 |

## 2. 네비게이션 & 사용성 (HR이 찾기 쉽게)

| # | 구분 | 현재 상태 | 개선 제안 |
|---|------|-----------|-----------|
| 2.1 | **Dock 순서** | About → Skills → Experience → Projects → Contact → Blog → GitHub → Terminal | **About → Experience → Projects → Skills → Contact** 순으로 변경. 경력·프로젝트를 먼저 보이게 해 채용 담당자 플로우에 맞춤 |
| 2.2 | **Dock 라벨** | "About Me", "Experience", "Projects" 등 | 툴팁만으로는 부족할 수 있음. 필요 시 아이콘 옆 **짧은 텍스트**(예: 소개, 경력, 프로젝트) 또는 첫 방문 시 **Dock 사용법 1회성 툴팁** |
| 2.3 | **Contact 가시성** | Dock 안에 있으나 "연락처"가 강조되지 않음 | Contact 아이콘/색상 강조 또는 "이력서 다운로드" 전용 버튼 추가 (2.6 참고) |
| 2.4 | **ESC 동작** | `ESC` 시 **모든 윈도우 + 웰컴 + 도움말** 한 번에 닫힘 | ESC는 "열린 윈도우만 닫기", 웰컴/도움말은 각자 닫기 버튼으로만 닫히게 분리. ESC로 전부 닫히면 실수로 웰컴까지 닫아 혼란 가능 |
| 2.5 | **도움말(Help)** | 개발자용 "구현 가이드", 기술 스택 설명 위주 | 인사담당자용 **"이 사이트 이용법"** 1섹션 추가: "어디서 소개/경력/프로젝트/연락처를 보나요?" (Dock 아이콘 설명), "이력서는 어디서 받나요?" 등 |

## 3. 콘텐츠 일관성 & 정확성

| # | 구분 | 현재 상태 | 개선 제안 |
|---|------|-----------|-----------|
| 3.1 | **재직처 표기** | **현재 재직: BARO Interactive** (InfoWidget 반영됨). About·Experience는 **과거 경력(BEO, GoodSen 등)** 이력용 | 과거 이력은 BEO/GoodSen 유지, 현재 재직처는 BARO Interactive로 통일. 이력서·LinkedIn과 동일하게 맞출 것 |
| 3.2 | **경력 데이터 중복** | AboutWindow(aboutData.js)와 ExperienceWindow, ProjectsWindow에 **경력/프로젝트가 각각 하드코딩** | 경력/프로젝트는 **단일 소스(예: aboutData.js 또는 data/career.js)**에서 export 후 About/Experience/Projects에서 import. 수정 시 한 곳만 고치면 되게 정리 |
| 3.3 | **Skills 이중화** | About 탭의 Skills와 **Skills 창**이 별도. About은 aboutData의 SKILLS_CATEGORIES, Skills 창은 다른 목록 | 스킬 목록도 **한 데이터 소스**로 통일. 표현만 "간략(About)" / "상세(Skills 창)"으로 나누기 |
| 3.4 | **프로젝트 링크** | ProjectsWindow에는 **Live/Repo 링크 없음**. About의 Projects 탭에는 liveUrl/repoUrl 있음 | ProjectsWindow 카드에도 **"사이트 보기" / "코드 보기"** 버튼 추가. 데이터 소스 통일 시 URL도 같이 관리 |

## 4. 포트폴리오 핵심 기능 (인사담당자 필수)

| # | 구분 | 현재 상태 | 개선 제안 |
|---|------|-----------|-----------|
| 4.1 | **이력서 PDF** | 이력서 다운로드 링크 **없음** | **이력서 PDF**를 `public/resume.pdf` 등으로 두고, Contact 창 + Dock/메뉴바에 **"이력서 다운로드"** 버튼/링크 추가. 인사담당자 1순위 액션 |
| 4.2 | **Contact 창** | 이메일, GitHub, 블로그, LinkedIn만 나열. 클릭 시 새 탭 | **한 줄 소개 + "이력서 다운로드"** 상단 배치. 이메일은 `mailto:` 유지, "연락 시 참고할 포지션" 문구 추가 가능 (예: 풀스택/백엔드 희망) |
| 4.3 | **About 요약** | Summary가 길어서 한눈에 안 들어올 수 있음 | 상단에 **2~3줄 한 줄 소개 + 핵심 키워드(풀스택, BEO, SaaS, Spring, Vue)** 태그 형태로 강조 |
| 4.4 | **성과 수치** | Experience/About에 Conversion 106%↑, Automation 70%↑ 등 있음 | **숫자는 더 크게/색상 강조**해 "성과 지표" 섹션처럼 보이게. 인사담당자가 스캔할 때 눈에 띄게 |

## 5. 경력·프로젝트 표현 (임팩트)

| # | 구분 | 현재 상태 | 개선 제안 |
|---|------|-----------|-----------|
| 5.1 | **Experience 창** | About의 Career 탭과 **내용 중복**. 애니메이션만 About이 더 정리됨 | About = 요약+스토리, Experience = **상세 경력 타임라인**으로 역할 나누거나, **한쪽을 없애고 한 곳으로 통합** (중복 제거) |
| 5.2 | **프로젝트 역할** | "Team Lead", "Solo Developer", "Toy Project" 등 | 각 카드에 **"내 기여 한 줄"** (예: "1인 풀스택 개발", "백엔드 API·DB 설계") 추가하면 차별화 |
| 5.3 | **기술 스택** | 태그만 나열 | "이 프로젝트에서 **주로 사용한 기술**" 1~2개 강조(예: 굵게/아이콘) 해서 스캔하기 쉽게 |
| 5.4 | **프로젝트 기간** | "2025.07 ~ Present" 등 | **총 기간** 표기 (예: "3개월") 선택 추가. 단기 프로젝트도 기간이 보이면 신뢰도 상승 |

## 7. 기술적·품질

| # | 구분 | 현재 상태 | 개선 제안 |
|---|------|-----------|-----------|
| 7.1 | **body overflow** | `showWelcome \|\| showHelp` 일 때만 `overflow: hidden`, 나머지도 `hidden`으로 설정됨 | 의도 확인. 스크롤이 필요한 페이지면 모달 열릴 때만 `hidden`, 닫히면 `''` 복원 |
| 7.2 | **접근성** | 버튼·아이콘에 `aria-*` 일부만 사용 | 주요 CTA(Enter Portfolio, 이력서 다운로드, Contact 링크)에 **aria-label**, 포커스 가능한 요소는 **키보드 포커스 링** |
| 7.3 | **모바일** | Window가 768px 이하에서 전체 화면 등 반응형 있음 | Dock이 작은 화면에서 **가독성·터치 영역** 확인. "About 먼저 보기" 같은 모바일용 짧은 가이드 한 줄 고려 |
| 7.4 | **이미지 경로** | `/Kyle.png`, `/taemin.jpg`, `image/Kyle.png` 혼재 | `public` 기준으로 **경로 하나로 통일** (`/Kyle.png`). 빌드 후 실제 배포 환경에서 이미지 로드 확인 |

## 8. 우선 적용 추천 (Quick Wins)

1. **InfoWidget** 현재 재직처 **"BARO Interactive"** 유지 (3.1). About/Experience는 과거 경력용  
2. **index.html** 타이틀 + **meta description** 추가 (1.2)  
3. **Contact 창** 상단에 **"이력서 다운로드"** 버튼 추가 (4.1, 4.2) — PDF 준비되면 링크만 연결  
4. **Welcome** 문구를 "1년 차 풀스택, End-to-End 개발" 등 **한 줄 요약**으로 변경 (1.1)  
5. **Dock 순서**를 About → Experience → Projects → Skills → Contact 순으로 변경 (2.1)  
6. **MenuBar** 로고 경로 `image/Kyle.png` → `/Kyle.png` (1.4)  
7. **경력/프로젝트 데이터**를 aboutData(또는 공용 data) 한 곳으로 모으기 (3.2, 3.3)

## 요약

- **첫인상**: 타이틀/메타/웰컴 문구를 "이 사람이 누구인지, 뭘 하는지"가 바로 보이게.  
- **네비게이션**: About → 경력 → 프로젝트 → 스킬 → 연락처 순으로, 이력서 다운로드 명확히.  
- **콘텐츠**: 재직처·경력·프로젝트·스킬 **한 소스로 통일**, 숫자·성과 강조.  
- **기능**: 이력서 PDF 다운로드, Contact 강화가 인사담당자 임팩트에 가장 큼.

원하면 위 항목 중에서 **먼저 적용할 번호**를 지정해 주시면, 해당 부분만 골라서 수정 예시(코드/파일 단위)까지 작성해 드리겠습니다.
